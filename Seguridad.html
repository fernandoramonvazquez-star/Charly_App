🔒 Transparencia Metodológica y Privacidad

Seguridad y Protección de Datos

Charly App ejecuta el motor estadístico R de forma local en su computadora. Este documento detalla qué procesos se ejecutan, qué datos se transmiten y cómo se protegen sus credenciales.

1. El código R se ejecuta localmente con sus permisos

El script de análisis (workspace/generated_script.R) es redactado por el modelo de lenguaje a partir de su consigna metodológica, pero se ejecuta de manera local en su propia máquina mediante el entorno de R instalado en su sistema.

  • El script se ejecuta con los mismos privilegios que su usuario de Windows en esa sesión.
  • Charly realiza limpiezas y correcciones de sintaxis automáticas sobre el script antes de ejecutarlo.
  • Control por el investigador: Charly abre automáticamente el script en RStudio al finalizar. Si analiza datos institucionales o sensibles, usted puede inspeccionar cada función convocada antes de reportar o utilizar las conclusiones.

2. Procesos del sistema y PowerShell

  • Los scripts auxiliares internos se ejecutan con -ExecutionPolicy Bypass exclusivamente para cada proceso hijo generado por Charly App. La política global de PowerShell de su sistema operativo Windows no es modificada.
  • Cualquier proceso en ejecución (cálculo en R, llamada a la API o servidor local) puede interrumpirse de inmediato presionando el botón ⛔ Cancelar en la barra superior.

3. Qué información sale de su computadora

Charly App ofrece dos modalidades operativas con distintos perfiles de privacidad:

Modalidad Qué información se transmite Destino
Modo Nube (Gemini) Su texto de consigna + la ficha descriptiva de la base (nombres de variables, tipo de datos, N total y cantidad de valores ausentes). No se transmiten filas individuales con respuestas crudas de los participantes. Servidor oficial de Google (generativelanguage.googleapis.com) vía HTTPS cifrado.
Modo Local (Offline / Seru Girán) La misma ficha descriptiva y consigna, pero enviada únicamente a la dirección local 127.0.0.1 de su máquina. Su propia computadora física. Ninguna información viaja a través de internet.
Recomendación para datos de alta sensibilidad: Si trabaja con bases de datos confidenciales con restricciones éticas o comités de bioética que prohíban la transmisión de nombres de variables a servidores externos, seleccione el Modo Local (Offline).

4. Protección de su Clave API de Google

  • Su API Key de Google nunca se almacena en texto plano ni se incluye en los scripts de R generados.
  • Se guarda cifrada en disco mediante la API de Protección de Datos de Windows (DPAPI) en %APPDATA%\Charly_App\settings.json. Esta tecnología vincula el cifrado a su usuario exclusivo de Windows en esa computadora particular; si el archivo se copia a otra máquina, no puede ser descifrado.
  • Durante la comunicación con Google, la clave se transmite únicamente en el encabezado seguro x-goog-api-key mediante el protocolo HTTPS.

5. Registro de actividad (Logs)

El archivo de registro técnico (%APPDATA%\Charly_App\charly.log) registra únicamente eventos del sistema (rutas de R detectadas, tiempos de ejecución o fallos de procesos). No registra claves de API, datos numéricos de los participantes ni el contenido de sus bases.

6. Buenas prácticas de trabajo

  1. Verificación independiente: Revise siempre el archivo workspace/generated_script.R en RStudio para verificar las decisiones metodológicas adoptadas.
  2. Resguardo de resultados: Los informes en Word y las salidas de consola se almacenan localmente en la carpeta de la aplicación; cópielos a su carpeta de investigación definitiva al terminar.
  3. Entornos compartidos: Si utiliza una computadora compartida de laboratorio, no comparta su sesión de usuario de Windows para mantener la protección de DPAPI sobre sus credenciales.
